# v0.14.0-beta.1：群内接话场景与反馈

本版本是待验证候选，不自动开启新能力，不修改角色卡，不执行群消息发送。旧的成员表达、喜恶和习惯资料继续使用原协议。场景模式是同群、同角色可借鉴的接话方法，不是任何成员的个人资料。

## 开关与审查

- `scene_learning_enabled=false`：同时控制场景分析、检索、场景使用/反馈采集。开启后沿用已有完整 UMO 白名单、分析模型和审查模型。
- `scene_disambiguation_enabled=false`：仅场景学习开启时有效。已准入、意图确实不明确或有待确认的幽默解释时，才补充一次分析模型调用。预算包含排队，最长约 5 秒，不重试。单纯未获得可选语义字段，不触发补充调用。
- `scene_pattern_review=llm`、`scene_adjustment_review=llm`；也可选 `llm_then_human`。这两类不能使用无 LLM 审查的自动或纯人工模式。
- 检视时配置的 `gemini-4-hydrogen-xhigh` 在三个独立困难场景探测中均超时回退，见候选目录的 evaluation/disambiguation.json；不因此延长回复等待或扩大调用范围。

## 学习、证据与检索

后台从已绑定角色的真人原始消息中沿可核对的明确引用链补齐上下文，每段最多六条，缺上游或成环时不采用。仅相邻或模型推测的同话题，不作为已确认回应链。新候选最多两项，至少三段不重叠对话、两位实际表达者、跨两个 UTC 日期。

模式包含 `scene`（沟通意图、表达方式、本轮用途）、`method`、`conditions`、`avoid`、`episode_ids`。程序复算支持门槛，生成至多两条 `derived=true` 的加工示例。原始证据保持原文；示例及方法文本过滤 @ 提及、已知成员昵称、账号、链接等。审查模型继续检查遗漏的身份线索，不把加工示例当原话，也不因具体游戏话题陌生而直接否定接话方法。

场景检索在决策结束、生成开始前进行，与旧资料预算分开，至多返回一个模式（一个简短方法、两条示例）。要求意图和表达方式一致；双方已知的回合用途不一致时不选择，例如分享成果不能套到晚安、附和或纠正误解上。再按证据支持、新鲜度、词面辅助匹配、近期重复使用及已审查惩罚排序。无匹配返回空。

按完整群会话和当前角色隔离，群体模式不进入私聊或旧 v1 投影。所有贡献者的来源标识仍交给回复插件现有成员边界过滤，不能靠去身份文本绕过边界。

## 可选伙伴接口

`learning_capabilities()` 按开关声明 `scene_learning_v1`，另按困难判断开关声明 `scene_disambiguation_v1`，原 `reply_projection_v1` 不变。

- `get_scene_context(scope, persona, member, scene=None, query='', frozen=None, **kwargs)`：同步仅读缓存，返回 `{schema_version:1, scope, persona, member, items, versions}`。`frozen` 是此前选定项的 `source_id/revision`，只核对该版本，不重新排序。项目携带来源群、全部贡献者、有效期、版本和模式正文。
- `disambiguate_reply_scene(scope, persona, member, turn_id, text, context, **kwargs)`：异步、有界，复用分析模型。输入先经过成员边界过滤，只取当前对象及 Bot 的有来源交流。输出仍为暂定场景理解，只用于选择表达模式，不改变参与权限、对象、动作或长度。
- `report_scene_event(record)`：同步、有界队列，记录 `selected`、`disambiguation` 的标识和耗时。模型输入阶段继续依赖现有 `report_reply_usage` 的材料指纹证明，并在其 `learning` 列表及 `scene_trace` 中关联场景版本和原学习回合。

Chat Dynamics 的每个回合至多补充判断一次；生成重试沿用冻结结果。插件替换、禁用、角色变化、撤回、过期或成员边界变化时，生成/发送校验会使使用旧场景的在途回合失效。旧伙伴无新能力时保持原链路。

## 反馈与诊断

`scene_receipts` 记录选取/实际进入模型输入/额外判断；`scene_deliveries` 记录成功送达消息；`scene_feedback` 记录针对该消息的后续互动；`scene_analysis` 保存已分析证据指纹。日志不新增原始模型提示词，反馈通过来源事件 ID 查证。新表随原有保留周期清理，删除会话一并清除。SQLite `user_version=8`，采用增量建表，不将旧样例自动转换为场景模式。

只有同群同角色、同一交流对象明确引用已送达 Bot 消息，且反馈到达在有界关联窗口内，才关联反馈。普通相邻发言、身份不匹配、对象不确定保持未知；晚到的送达与输入证明可补齐关联。

“我是在开玩笑”“不是这个意思”等明确纠正可附带后续说明。问句、引用中的纠正词不机械当作本人反馈。已确认引用且语义判断为继续同一个梗的内容只记弱证据，单独笑声、发送成功和沉默均不加分。模型预测不是标签真值，模式进入模型也不证明模型采用了它。

针对同一模式版本的两次独立回复出现明确纠正，生成 `scene_adjustment`，经审查后将该版本检索优先级乘以 0.5。待审调整不影响排序；新版本不会继承未经审查的惩罚。当前纠正仍由回复插件已有回合理解即时处理，长期调整走版本审查和回滚。

总览分别显示模式存量、检索候选、进入模型输入、关联已发送回复、可归因反馈，并显示额外判断次数、记录回合数、比例、超时和累计等待。接口还提供等待 P95。除模式存量外，统计窗口为最近 24 小时；这些数值不是自然度评分。

## 发布与回退

本轮只产出隔离候选与离线评估，不修改线上源码、配置、数据，也不重载插件。新能力均默认关闭。配套回复插件改动以基于捕获源码的补丁/覆盖包提供，应用前必须核对基线清单，避免覆盖其他任务的新修改。

关闭两个开关即可停止新能力并继续旧回复链；学习记录保留。单项内容可走已有撤回/回滚入口。旧插件不理解新类别，直接降级前应保留数据库一致性备份；优先通过新版本关闭能力回退行为。
