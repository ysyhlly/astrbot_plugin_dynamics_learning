# 按群处理待审内容

打开「调整审查」默认查询全部已启用群的 pending/reviewed 记录，不含已应用、已拒绝、已回滚记录。选择单个群后，可批准本页或跨页勾选同群多个成员；每页 50 条，每次最多 100 条。切换群、搜索词、类别、状态或可批准筛选会清空选择，翻页会保留选择。

「可批准」「全部待审」计数是当前群范围、搜索词、类别和状态条件下的全量计数，先过滤再分页。「全部群」提供统一查找，批量提交需先选择单个群。完整 UMO 区分账号相同但平台或 Bot 不同的群。

查询支持提案内容、关键词、理由、群会话、成员账号以及已观察到的昵称。未缓存到的昵称可用账号查询。搜索只读取必要的提案字段，原始证据按需展开。

批量提交只批准明确列出的 id 和 updated 版本，不接收搜索条件来隐式批准后续出现的新记录。仍检查审查模式、LLM 结果、当前人格、适用范围、资料有效期、学习项基线以及固定性格规则；任一记录失效或事务执行失败，整批不应用。成员资料 LLM 自动生效、好感度自动生效的配置保持不变。

每项写入自己的成员和人格归属，保留单独审计与回滚；批量操作不会合并资料，也不会绕过旧学习项的版本冲突。

## 批量 LLM 审查和拒绝（v0.10.0）

同一套跨页选择可以执行批准、LLM 审查或拒绝。没有勾选时按钮作用于本页符合条件的项目；勾选后作用于所选项目。确认弹窗明确列出参与项和跳过项，不会把已通过、自动好感度或当前不允许 LLM 审查的项目重新发送审查。

LLM 任务按原有模型调度逐项执行，页面每 5 秒更新进度。单条失败不撤销已完成结果，并继续其他条目。成员资料通过后依配置自动生效；其他类别保留已有人工确认要求。任务显示最近 10 批的逐条结果，已结束记录按保留周期清理；重载会标记中断，需刷新待审内容后重新选择尚未完成的项目。

批量拒绝可填统一理由，记录到每项审查历史。任一版本失效则整批拒绝不提交；不会撤回已生效资料。所有真实操作仍需要确认弹窗最终提交。

## 暂停、取消和失败重试（v0.11.0）

展开「批量 LLM 审查」中的任务即可操作：

- 暂停：当前正在审查的条目完成后暂停，不再启动后续项；排队尚未开始的任务直接暂停。
- 恢复未完成项：保留已完成、失败和跳过记录，仅继续排队或中断的未完成项。暂停状态跨插件重载保留。
- 取消剩余任务：确认后停止启动后续项，丢弃尚未提交的模型结果。已经发出的请求可能继续到返回或超时；已完成或已进入提交的结果会保留，不回滚已生效资料。
- 重试失败项：一键创建关联批次，只重试失败项，重新校验提案版本、角色和审查条件。已变化或已处理的失败项会跳过；通过、拒绝、需补充证据和主动取消的条目不会因此重跑。

原批次记录完整保留，重试在新批次显示；若再次失败，从最新重试批次继续操作。暂停任务不会被常规过期清理，但主动删除群学习数据会同时删除任务。

## 一致性保证（v0.11.1）

审查结果与任务回执同事务提交，自动生效与其回执同事务提交；未完成提交会整体回滚。已经保存的审查或生效结果不会因后续刷新失败而被标记为 LLM 审查失败。若显示后续生效/刷新异常，先核对已学内容与配置，不要重新发送已经通过的 LLM 审查。

普通任务取消和插件重载会等待已开始的数据库写入完成再退出。中断记录可继续恢复；结果保留期从最近更新计算，旧任务刚完成时不会因创建时间较早而立刻清理。

模型服务与本地数据库之间不存在分布式事务：如果进程在请求已发出、结果尚未持久化时被强制终止，恢复可能需要重新请求模型。这里保证的是已提交结果与本地回执的一致性，不承诺外部模型调用绝对仅发生一次。
