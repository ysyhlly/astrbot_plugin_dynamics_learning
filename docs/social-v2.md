# 黑话、好感度与群友关系

群间学习 v0.2 内置原群友关系分析插件 2.1.2 的 MIT 统计核心，以完整 UMO 替代裸群号，补充与统计同事务的消息来源去重。它拥有独立数据，不导入运行中的原插件模块。

## 三种资料

- 黑话：按群保存已确认词语、释义和来源，当前消息命中时才注入。新词和改义进入原有审查流程；管理页可以搜索和提出词义纠正。
- 好感度：角色对当前成员的亲近趋势。沿用现有的经验曲线及十进制精度，100 是参照，没有 100 分上限；越高增长越慢。稳定关系和一天内的临时语气分开保存，历史的明确保持距离标记保留。
- 群友关系：近窗口内的活跃成员、互动广度、均衡、互惠、正负语气、明确引用/@往来与互动圈。它描述已观察群聊，不推断现实身份、情侣关系或完整群成员名单。

Bot 决策与回复同时得到当前发言者的好感、相关伙伴、代表往来、活跃分布和命中的黑话。数据在回合开始冻结；后续正常聊天不会取消在途回复，审批、回滚、停用或删除仍能使使用旧版本的回复失效。

当前群有新记录接管时，Chat Dynamics 从旧 SelfLearning 材料中去除对应的好感和黑话，表达习惯等其他材料保留。未由新记录接管的成员、群或人格仍可使用原有资料。原插件自身的源码、配置、命令和数据库不因本次接入而改写。

## 审查与关系连续性

新增 affection 提案使用 `bot_affection` 键，包含 experience_delta 和可选 tone。单条提案最多改变 20 点经验，没有每日总量或全局好感度配额。证据必须来自同一成员、同一群和角色；同一个原消息不能因 observed/decision/outcome 三个阶段重复奖励。回滚恢复之前的经验和语气。

黑话和好感变化默认仍为 LLM 初审＋人工确认。管理员纠正现有词条会生成新提案，不直接覆盖已生效词义。原有已确认黑话和历史好感是迁移基线，不伪装成新的群友反馈或新获批准的调整。

表达与策略仍绑定人设文本指纹。稳定好感另外保留完整会话、persona_id、instance_id 的原始角色身份；同一角色修改设定文本不会把其亲近历史归零，更换角色身份不会借用另一角色的记录。

## 数据迁移

`migration_social.py` 默认只预览，指定 --apply 和已核对 fingerprint 后才写目标。源数据库使用 SQLite 只读连接，运行中的源库应先通过 SQLite backup API 取得一致快照。目标必须是停用插件后的数据库或离线副本；禁止指向源文件。

迁移范围只接受明确的完整群 UMO。两个平台账号出现相同裸群号时拒绝猜测映射；私聊伪群记录不导入。优先保留能够核对完整角色 scope 的好感；旧裸群历史只在对应已选群中作为后备基线。

黑话按原 SelfLearning `only_confirmed` 口径迁入：is_jargon 为真、有词义、非跨群全局条目且未处于待删除阶段。is_complete 是旧流程进度标志，不把它误当成确认真值。候选、空释义和其他群条目保留在原库。

群关系的 users/messages/relations/relation_daily/member_daily/directed_events 及观察起点、每日衰减日期一起迁入。原有统计窗口、计分权重、衰减与共享情感模型开关可映射到新配置。对来源快照和目标逐表核对；已迁过的指纹不重复导入，非空目标关系区不做叠加导入。

迁移记录保存在 social_imports；原始字段与来源表/行号保存在 legacy_social。成员首次在新接口产生当前角色快照时绑定其历史记录；没有足够身份信息时保持未知。

原始群友关系算法保留 MIT 作者归属，见 vendor/group_relations/NOTICE.md。SelfLearning 仅作为数据格式与功能兼容来源，新实现不依赖其运行时模块。
