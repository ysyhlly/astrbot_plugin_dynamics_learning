# 学习与验证架构

## 职责边界

| 模块 | 职责 |
| --- | --- |
| samples / ingest | 保存宿主事实、标签来源和三类时间，生成任务样本 |
| metrics / bootstrap | 共用指标定义，输出指标版本 |
| evaluation_plan | 从实际变更参数确定目标、受影响任务和回放未覆盖参数 |
| evaluator | 对固定参数评分，报告基线复现差异 |
| evaluation_pipeline | 预留验证数据、持有分析快照、统一收尾所有候选 |
| report | 汇总统计、评测和建议供查询展示 |
| store / main | 检查证据身份、执行状态转换、保存与提供策略 |

候选生成器只接收 development 数据。最终会话留出和时间留出在生成前划定；同一消息派生的多个任务不能跨越最终时间边界。EvaluationContext 复制输入数据，并在验证前检查快照是否被生成器修改。关闭 tuning 不会绕过统一收尾。

每份最终证据绑定候选参数哈希、基线哈希、数据内容指纹、切分指纹和 metric_schema_version。存储状态转换不允许旧口径证据被当作当前验证结果。旧记录仍可读取，启动时已有的证据失效检查会将不匹配策略标为过期，需重新分析。

## 指标与目标

指标版本为 2。Pair Accuracy = (TP + TN) / pairs；F1 = 2TP / (2TP + FP + FN)。零分是有效值，分母为零才是未定义。Bootstrap 复用同一公式。话题学习的原始表现来自记录标签，不再借用零阈值假设回放。

当前保留 pair_accuracy 作为话题主目标，F1 作为退化保护，不隐式更换成新的成本函数。

strong_addressivity_threshold 影响 recipient 和 reply_admission，两者都必须有足够验证证据；topic_commit_threshold 影响 topic。其他阈值在当前回放中不能获得完整验证，保守返回 insufficient。联合变更预先固定 recipient、topic 的目标顺序，所有受影响任务均检查退化，不根据最终留出集表现选择主指标。

## 数据语义和兼容

样本 schema 4 增加 event_at、ingested_at、label_source、label_revision。annotated_at 缺失保持 0（未知）；timestamp 继续作为标注时钟的兼容别名，时间前向验证仍然回答更晚标注的数据是否成立。未知时间不作为较晚数据进入时间留出集。

事件时间和导入时间不会替代标注时间；旧样本不推断人工来源或标签修订。数据内容指纹保留标签与事实语义，排除纯导入时间，避免同一内容重新读取就使结果过期。

新鲜度报告近期样本量、近期占比、未知或无效时间占比；近期样本量必须满足已有 gate_min_samples。概览同时提供任务行数、独立消息数和会话数，不能把多任务派生行解释为独立消息。

## 能力边界

基线复现诊断将记录中的 recipient / admission 决策与基线回放比较，列出可检查、差异、排除数量。差异本身不证明宿主错误，可能来自真实配置或缺失轨迹。话题原始指标与候选回放分开记录。

这里仍是记录轨迹上的局部离线验证。预留集不自动成为按独立抽样规则建立的人工审计集；label_source 为 unknown 的旧记录也不因此获得人工证明。未实现完整群聊状态模拟，未改变宿主的参与决策模型。策略状态变化与宿主真实读取、在线采用和收益仍是不同事实。
