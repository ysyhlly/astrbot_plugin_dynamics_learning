# 回复复盘与角色验收边界

## 已修复

- 复盘身份使用会话与消息 ID 的组合哈希；同名跨会话消息独立匹配，歧义旧响应弃权。
- 没有正文、非布尔判断、无效或零置信度不计入判断数。未知发送结果不当作未发送。
- 规则未准入与模型都倾向沉默时显示“未准入；发送未知”，不会显示“回了”。
- 未发送与模型倾向回应只算意见差异；门禁、角色选择、生成和发送失败不能证明规则漏回。
- 模型读取有限的历史上下文；人工答案、最终动作、门禁及发送结果仅在模型返回后对照。
- 当前宿主未保存足以复盘角色意愿的历史参与原则；人设模式明确弃权，不用当前人设替代历史。
- 面板沿用默认关闭、按钮触发和正文不落盘约束；复盘不会生成训练标签。

## 尚需真实对话人工验收

以下场景是验收清单，不能把单元测试通过理解为生成风格已经通过。每例分别记录发言对象、可接受动作、发送约束和实际回复风格。

| 场景 | 验收要求 |
| --- | --- |
| A 对 B 说“安安又睡了” | 谈论角色不等于向角色发问 |
| 角色问“还继续吗”，对方答“嗯” | 结合前一问识别回答，不机械忽略短句 |
| 陌生人连续搭话 | 延续对话不自动建立亲密关系 |
| 熟人明确找角色 | 允许简短回应或拒绝，不默认热情接单 |
| 两条话题交错 | 回复对象和关系证据不跨线程挪用 |
| 入睡后普通群聊与明确请求 | 按既定短醒规则，短醒后恢复安静 |
| 命令角色做不想做的事 | 区分回应、拒绝和执行；沉默可为可接受动作 |
| 戳一戳与线上拥抱 | 不强制口头表达、俏皮、真实接触或亲密互动 |
| 收尾后无关新消息 | 不强行追加问题或续聊 |

现有布尔人工标签不能表达完整动作集合。角色回复质量审阅、可接受动作标注和长期关系上下文属于后续功能，
本轮没有引入综合角色分或将模型意见当成人工真值。角色像不像仍需必要的真实回复正文和人工验收。
