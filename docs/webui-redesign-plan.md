# Dynamics Learning 页面重写规划

状态：已实施，随 v1.4.0 发布。基于 v1.3.2 页面及接口核对。

## 目标与范围

把现有长报告页改为可连续操作的学习工作台：找到需要检查的会话，查看证据，补齐数据，评估候选，再决定策略状态。

重写 `pages/learning/` 的布局、组件、状态管理和交互。保留已有统计、样本、复盘、窗口导出、评测、影子观察与策略功能。第一期沿用后端契约和轻量静态页面交付方式，不改学习算法，不引入运行时 CDN。

已确认方向：用户选择“按会话排查问题，再查看证据和建议”，工作台作为默认首页。

## 现状依据

- 页面仅有“总览 / 会话画像”两个入口，总览承载十余个连续区块。
- 首屏先呈现长篇契约说明；导入、分析、导出同时常驻顶部，缺少随当前状态变化的操作重点。
- 画像与样本已支持会话过滤，但当前样本浏览没有接入会话选择。
- report、shadow、policies 等结果主要面向全局，不能假装随会话选择自动过滤。
- 现有样本接口不提供消息正文、真实群名称或头像；设计不依赖这些不存在的数据。

以上是代码与接口结构判断，尚未作为新版视觉稿或真实宿主体验验收。

## 信息架构

| 栏目 | 用户要解决的问题 | 内容与主要操作 |
| --- | --- | --- |
| 工作台（默认） | 先检查哪个会话，问题在哪里？ | 会话列表、画像、错误方向、样本证据、下一步建议 |
| 数据与复盘 | 数据够不够，还能补什么？ | 导入状态、数据门槛、可标注窗口、契约详情、模型复盘、导出 |
| 评测 | 候选比基线好在哪里，结论可靠吗？ | 基线/候选比较、有效样本、排除样本、前向验证、置信区间、调参过程 |
| 影子观察 | 在线比较覆盖如何，是否支持继续推进？ | 实际流量、带标签分歧、净收益、时段与会话覆盖、门槛 |
| 策略 | 当前有哪些候选，如何推进或撤回？ | 版本列表、参数差异、证据、状态历史、后端允许的动作 |

五个栏目保留为同一个 AstrBot 插件入口内的视图，使用 hash 记录视图和会话选择，支持刷新恢复与浏览器返回。

## 默认工作台

桌面采用侧栏导航、会话列表和详情区。内容宽度随宿主 iframe 调整，不依赖窗口全屏。

1. 顶部：页面标题、最近导入/分析时间、当前数据状态；只突出一个下一步操作。
2. 会话列表：匿名会话标识、被检查样本数、证据充分度、主要问题。支持搜索已有标识与按已有字段筛选；默认按样本量排序，不凭空生成风险评分。
3. 详情摘要：主要问题、证据是否足够、建议查看的任务。
4. 详情页签：画像 / 样本证据。画像使用服务端对其他会话的比较结果；样本按完整 scope hash 请求并分页。
5. 样本展开：预测、人工标签、错误类型和已返回的证据码。正文不伪造，未提供的详细 trace 不用占位内容冒充。

顶部状态只表示当前能做什么：未导入时“导入标注”；已有数据未分析时“运行分析”；数据门槛未过时“查看缺失项”。不能把后台分析耗时伪装成百分比进度。

## 关键交互

- 数据门槛：始终显示整体结果与阻断原因；长说明和原始字段按需展开。
- 评测：先显示判定与依据，再展示具体指标；同时显示有效支持数和不可回放数量。
- 影子观察：实际流量和人工标签统计分别命名，分别展示分母；状态阶段不能代替在线观测证据。
- 策略：默认展示版本、状态与改动摘要，点击查看证据。按钮来自 `available_actions`；“采纳”说明为本插件记录，不显示“线上已生效”。
- 复盘：明确区分确定性结论与模型解释。进入栏目不自动触发模型请求；用户点击才请求，默认优先缓存，重新生成另设动作。
- 导出：放在对应数据区和更多操作中，保留原有导出类型；第一期不新增清空数据入口。
- 全局结果明确标“全局数据”。切换会话只影响画像和样本，不影响全局分析、策略或复盘的范围。

## 视觉方向

采用克制的工具型界面：保留现有绿色强调色和中性背景，减少每个区块都套大卡片的做法。侧栏与工作区分层，表格对齐数字；标题、结论、证据形成清楚的三级层次。

- 主强调色用于当前导航和主要操作；红色仅用于故障或已确认回归，未知状态用中性色。
- 基础字号 14px、正文约 1.5 行高；间距以 4/8px 为单位，圆角控制在 6–10px。
- 保留明暗主题，服从宿主 `data-theme`，不覆盖宿主主题属性。
- 不使用装饰性大图、渐变英雄区或无意义仪表盘；比较图只绘制真实返回的数据，区间缺失时不画区间。
- 以容器宽度划分布局：宽屏并列列表/详情，中屏压缩导航，窄屏列表与详情逐层进入并提供返回入口。

## 状态与可访问性

每个视图单独处理首次加载、空数据、旧数据更新中、部分失败、不支持和成功。更新失败保留旧内容并标注时间，只重试失败部分。未知数字显示“未知”或“—”，不折算成 0。

会话切换丢弃过期响应；切换任务过滤器回到第 1 页。导航、页签、分页和展开项支持键盘，焦点可见，状态不单靠颜色。关闭详情后焦点回到原列表项。减少动画设置生效。

## 代码拆分与接口

| 文件职责 | 建议位置 |
| --- | --- |
| 页面骨架、语义导航 | `index.html` |
| 主题、排版、间距 | `styles/tokens.css`、`styles/base.css` |
| 工作区布局与响应式 | `styles/layout.css`、`styles/components.css` |
| 启动、路由与事件协调 | `app.js` |
| 桥接、超时、错误转换 | `api.js` |
| 视图状态、请求序号、筛选 | `state.js` |
| 空态、表格、状态标识等 | `components.js` |
| 五个栏目渲染 | `views/workspace.js` 等 |

第一步先验证宿主带 token 的静态资源加载是否支持拆分脚本；采用支持的加载方式，不预设 ES module 相对路径一定可用。无需框架迁移。

接口复用：工作台用 overview/scopes/scope/samples；数据页用 quality/annotation_window/review/reply_review/ingest/export；评测用 report/analyze；影子页用 shadow；策略页用 policies/policy。其他只读发布接口维持原契约。

## 实施顺序与验收

1. **锁定内容映射与状态样本**：每个旧区块对应新栏目，准备无数据、正常、有阻断、部分失败四类数据；避免迁移漏功能。
2. **完成工作台原型**：先打通会话选择、画像、样本分页这条真实路径，检验宽窄布局与主题。
3. **迁移数据、评测、影子和策略视图**：共用组件，逐个接入真实接口；不同时重写后端算法。
4. **删除旧渲染并回归**：确认功能映射完整后移除旧大文件逻辑，更新有行为价值的测试。

快速验证：JS 语法、版本无漂移、现有 Node 回归与新增会话切换/范围标记测试。

信心验证：真实 AstrBot iframe 中检查资源 token、明暗切换、首次打开、返回恢复、400/500/超时、快速切会话、分页、合法策略动作、复盘缓存与窄屏键盘访问。模拟桥接用于自动回归，不能代替真实宿主验证。

验收重点：旧功能全部有入口；首页能直接选择会话；全局/会话范围不混淆；失败只影响对应区域；未知数据不冒充结论；宿主主题和资源加载正常。

首个实施动作：搭建工作区骨架，接入 scopes → scope → samples 三个接口，先交付可检验的会话排查路径。
