# v0.14.0-beta.2：本群表达习惯

此候选补充长期表达习惯学习，保留 beta.1 的场景学习。它把“群友怎样说话”和“Bot 可借鉴哪些形式”分开保存，不修改角色身份、立场和自身喜恶。目标为明显群聊化，仍需真实使用验证；本轮不部署。

## 默认配置与数据边界

`expression_style_enabled=false`。开启后只作用于已有白名单群和当前角色，群体风格不进入私聊。`expression_style_review`、`expression_adjustment_review` 默认 `llm`，也可选择 `llm_then_human`；不提供绕过 LLM 审查的模式。原场景开关及困难判断开关仍默认关闭，表达适应本身不增加回复时模型调用。

成员 `style/typing_habit/preference` 保留原定义。新类别 `expression_style` 是群体形式，`expression_adjustment` 是经过审查的降权。旧记录不自动升级为群体风格。

## 均衡取样和审查

从已核实来源的原生单条消息中取样，无需都是明确回复。短反应也计入统计；玩笑和吐槽条目必须另有完整引用对话支持。已有跨天资料时，按日期分层，避免活跃群最近几十条全在同一天而永远无法学习。

每位贡献者取十条，最多六位近期有足够资料的成员，因此一人刷屏不会增加权重。最低三人、三十条、跨两个 UTC 日期。稀疏成员继续保留个人观察，不凭几条消息推断群体共性。统计按成员等权，包含句长、短句、换行、标点、近似表情、连续补充及重复语气词。

每个条目分开存 `observation` 和 `guidance`，引用至少三条来源、至少两位成员。具体口头禅还必须跨两个日期重复出现；偶发错字不学习。原文证据保留，示例去身份并标记 `derived=true`，不作为 Bot 的经历。昵称、账号和个人事实仍需独立审查。

程序过滤无证据条目；基础写法（句长、碎句、标点）和带口吻/示例的增强版本分别送审，最终每轮最多应用一个通过版本。不通过的增强项不能撤掉已通过基础项。两个候选均通过时采用增强版，基础候选记为“本轮已选择另一版本”，保留它的通过审查记录；这不表示 LLM 拒绝了基础写法。人工模式则保留选择权，应用任一版本后另一候选失效。

所有指导自动附带“仅在轻松闲聊且意思已说清楚时，可参考”的适用条件；审查员能看到程序执行的 `applicability`，仍需独立检查来源和口吻。安静或温和不等于必须正式，但统计上的短句也不能变成所有回复一律缩短。

首次可以使用已有近期证据。之后每群、每角色二十四小时最多一次分析/更新轮次，并至少新增二十条已绑定原生消息。即使模型失败，本轮不会立刻反复重试分析；待审记录可继续通过已有审查流程处理。新消息采用持久递增计数，保留期删除不会使调度游标倒退。候选保留原审计、版本和回滚规则。

## 回复接口与控制

新增可选能力 `expression_style_v1` 和同步缓存接口：

`get_expression_style_context(scope, persona, member, scene=None, action='', query='', frozen=None, **kwargs)`

返回 `{schema_version:1, scope, persona, member, items, versions}`，最多一个风格项目。项目包含来源、版本、有效期、选择参数，以及一段指导和加工示例。`frozen` 传入已选项目的 `source_id/revision/selection`，验证原选择，不因后来新消息或重复统计变化而改写在途输入。

- 闲聊采用至多三项指导；有通过审查的口吻条目时为其保留位置，避免始终只取句长和标点。口吻条目按当前输入确定性选择，无随机模型调用。
- 任务、倾诉和纠正不投影群体风格；用途不明仅允许标点形式，不用碎句压缩或示例。收尾仅选择长度/结尾，不添新话题。
- 具体成员已有明确交流偏好时优先于群体习惯。当前“太正式、别解释、别每次都问、不要老用这个词”可立即进入本轮约束，不等待长期学习审批；引用或问句中的词不机械当作纠正。
- 场景、群体表达和成员原话合计最多两条示例，跨通道去重。冻结原件不被裁剪修改；实际进入模型的示例 ID 才记录为使用证明。
- 实际已送达回复出现过的已学口头禅，在最近两条回复/一小时窗口内抑制；最近两次模型输入的示例也轮换。输入过某词不等于 Bot 说过，示例轮换只控制提示词多样性。
- 配套回复插件在带记忆背景和不带记忆背景的主回复路径都记录经过边界后的模型输入证明；撤回、过期、停用、角色变化或成员边界变化仍使在途学习版本失效。

## 反馈与存储

新增 `too_formal/overexplaining/repeated_question/repeated_phrase` 反馈类型，沿用 beta.1 的明确引用、同群、同角色、同一交流对象及已送达消息约束。审查材料同时包含关联的实际 Bot 回复、反馈原文及目标风格版本，明确标记 Bot 文本不属于群友训练来源。

两次独立明确纠正只生成待审降权建议，不直接改风格。通过审查后，该版本适应预算从最多三项降为一项、停用示例；当前目标版本已变化则不再应用旧惩罚。沉默、发送成功或单独笑声不加分。关联和投影仍不证明模型采用或因果改善。

新增 `expression_analysis`、`expression_deliveries`、`expression_source_counts`，数据库版本 9。实际输出重复记录按既有保留周期清理；删除会话同时清除调度和重复状态。原数据及其他学习类别保持原语义。总览新增“表达习惯（有效）”和开关状态，版本资料仍可在已有资料中心检查。

## 验证与回退

候选测试覆盖均衡贡献、短反应、跨日、偶发词、日更新限额、二十条新消息、基础/增强审查、一次应用、各回复用途、私聊与跨群隔离、重复抑制、共享示例预算、实际 provider 证明、当前纠正和撤回阻止发送。

三组离线对照使用固定人设、固定回复模型，包含十个匿名真实闲聊片段、十个补充闲聊案例、十个任务/纠正/边界案例。真实训练与测试按对话划分。模型盲评和真实用户满意度分开报告，完整结果见工作目录的 `VALIDATION-beta2.md`。

关闭表达开关即可回到原回复链，记录保留。候选包不包含线上配置、原始聊天数据库或凭据；配套源码覆盖需先核对基线，避免覆盖其他任务修改。
